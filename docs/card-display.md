# 卡面展示体系（决策记录，2026-09-25 用户拍板）

## 背景

B1 验收发现 YGOPRODeck 卡图全部为英文卡面。百鸽 CDN 虽有简中卡图目录 `/ygoimg/sc/{cardid}.webp`，但只对实际发行过简中版的卡有效——大量卡（尤其新卡）根本没有简中实体卡图。强行凑"全套简中实体卡图"不可行。

## 决策（用户原话为准）

> 不要求所有卡拥有官方简中完整卡图。卡牌核心展示使用 Card ID 对应原画 + 中文数据库动态渲染游戏卡面。官方简中完整卡图若存在，可作为详情页资源；不存在时允许使用日文/英文原始卡图作为收藏/参考图。中文名称和效果始终由 YGOCDB 数据库独立显示。

## 资源三层

| 层 | 用途 | 来源 | 存储 | 状态 |
|---|---|---|---|---|
| L1 原画 | **场上/手牌卡面渲染**（游戏自制中文卡框：中文名/种族/类型/效果/攻守全部来自 cards_clean.json 动态渲染） | **YGOPRODeck `images/cards_cropped/{id}.jpg`**（B2 实测：唯一无框纯插画源；百鸽 `!art` 是带框裁切，已证伪弃用） | `data/art/{id}.jpg` | ✅ B2 完成（样本 22 张验证） |

文字侧已就绪：`cn_name`（14281/14281）、`desc` 中文效果（14281/14281）都在 `cards_clean.json`，渲染无数据缺口。

## UI 侧约束（Phase 7 工单必须遵循）

- 场上/手牌：简洁中文卡 = 原画 + 中文名 + ATK/DEF + 表示形式（不缩印实体卡面小字）
- 点开详情：完整渲染卡面（大字中文效果）+ 实体卡图（L2 有则用，无则 L3）
- 效果：不受"有没有官方简中卡"限制，全部卡界面统一，中文字体可做大，加新卡零成本
